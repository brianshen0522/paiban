## 結論

登入、YTS 搜尋、電影頁、下載（真的用 WebTorrent 下載）、下載頁、片庫和儲存空間都做好了，你本機的部署已經接上 yts.gg，可以直接用。外觀可以選三種，手機寬度可用。還沒做的列在下面，包括邀請和註冊：**目前只有 `.env` 裡的管理員一個帳號能登入**。

## 做了什麼

- **YTS 網址**：上網查證目前是 `https://yts.gg`（yts.bz、yts.lt 都轉址到它，yts.mx 已經不存在）。已經設定在你本機的部署裡，測試連線回應正常（片庫 77,580 部）。錄了它的真實回應換掉手寫範例。
- **登入**：帳號密碼（argon2id）、session cookie（資料庫只存雜湊）、登入嘗試次數限制、防跨站請求、第一個管理員由 `.env` 建立。
- **外框**：頂端列（站名、搜尋、容量指示、通知、帳號選單）、側邊選單（手機上變成一排按鈕）、外觀切換（帳號選單和登入頁）、提示訊息、即時更新（SSE）。
- **搜尋**：關鍵字、畫質、類型、評分、排序、分頁；載入中、沒有結果、YTS 連不上、回應看不懂、還沒設定網址，各有畫面。
- **電影頁**：每個版本能不能直接播、預覽檔要預留多少、放不放得下、誰已經有了；下載、加入片庫、重試；空間不足時在那一列下方說明差多少。手機上版本表變成一個版本一張卡。
- **下載**：admission（容量上限加磁碟本身的空間，同時搶最後一點空間只有一個成功）、`torrent` 服務（排程、暫停、繼續、重試、停滯、失敗不刪檔、完成、做種、移除、重啟接續）。下載頁有即時進度、暫停／繼續／取消／重試／移除（都有就地確認框）。
- **片庫、儲存空間**：片庫列出下載完成的片並可移除；儲存空間頁有用量、規則和自己持有的項目。
- **管理頁**：來源設定（YTS 網址和測試）、下載設定（同時下載數、限速、停滯、tracker、做種、預覽檔）、儲存空間管理（容量上限和所有項目）。
- **唯一的刪除模組**：只有它刪 `/data` 底下的東西，而且只在有人按下移除之後；有原始碼掃描的測試守住。
- **本機開發**：`pnpm dev` 一個指令起資料庫、假的 YTS、本機做種、api、下載程式和網頁，不需要網路和金鑰。

## 和規格不同的地方

`docs/changes.md` 2026-10-06 的四則：階段順序、外觀三選一、資料庫改用純 SQL 遷移（不用 Drizzle）、連入狀況只看 TCP。另外合約和對齊核心已經搬進 `packages/shared`（原本階段 1 的第一步）。

## 發現的問題

- 海報會從 yts.gg 轉址到 img.yts.gg，原本的程式不跟任何轉址，所以拿不到；已修正（只跟同網域或子網域，每一跳重新檢查）。
- 假的 YTS 沒有海報，所以開發環境的瀏覽器 console 會有一排 404（每張卡片一個）。不影響畫面（會畫佔位海報）。
- `deploy/.env` 的 `STORAGE_LIMIT_GB` 預設 50，所以你的容量上限目前是 50 GB。磁碟大小、要設多少請到「儲存空間管理」改。
