# 17 視覺與文案

原型的樣子就是要做的樣子。這份文件把它的規則寫出來，讓實作時不用從截圖去猜。

完整的樣式在 `prototype/platform/src/app.css`（平台）和 `bench.css`（工作台），兩個檔加起來四百多行，可以直接當作 CSS 的起點：token 照搬，類別改成元件。

## 方向

像一個家裡的影片櫃：固定的頂端列和一條短短的側邊選單框住一個工作頁面。頁面本身是安靜的表格、卡片和狀態標籤；唯一有顏色份量的東西是海報和一個琥珀色的主要按鈕。

不要做的事：漸層背景、大圖橫幅、毛玻璃、陰影堆疊、圖示庫、動畫轉場、圓角過大的卡片。這是一個每天用的工具，不是產品首頁。

原型的 CSS 另外有幾個不是顏色的變數：`--r`（8 px，按鈕和輸入框的圓角）、`--font-ui`、`--font-mono`、`--font-poster`（三組字型），以及每張佔位海報自己的 `--p`（底色）。

## 字

| 用途 | 字型 | `font-family` |
| --- | --- | --- |
| 介面 | IBM Plex Sans；中文用系統字型 | `"IBM Plex Sans", "PingFang TC", "Microsoft JhengHei", "Noto Sans TC", "Noto Sans CJK TC", system-ui, sans-serif` |
| 數字、時間碼、檔名、info hash、位移和速率 | IBM Plex Mono，並開 `font-variant-numeric: tabular-nums` | `"IBM Plex Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace` |
| 佔位海報上的片名 | Oswald，全大寫 | `"Oswald", "PingFang TC", "Microsoft JhengHei", "Noto Sans TC", sans-serif` |

**字型由網站自己提供，不從外部載入**（原型為了方便用了 Google Fonts，正式版不可以）。IBM Plex Sans、IBM Plex Mono、Oswald 用 npm 上的字型套件；中文不另外打包字型，用系統的。

字型的順序和原型的 CSS 不同：原型把 Noto Sans TC 排在系統字型前面，因為它從 Google Fonts 載入了那個字型。正式版沒有載入它，所以各平台自帶的中文字型（macOS 和 iOS 的 PingFang TC、Windows 的 Microsoft JhengHei）排前面，Noto 留給 Linux 和 Android。

字重：IBM Plex Sans 用 400、500、600；IBM Plex Mono 用 400、500；Oswald 用 500、600。只打包這幾個。

基準字級 14 px、行高 1.5。頁面標題 21 px / 600；卡片標題 15 px / 600；說明文字 12.5 px；大數字（用量）28 px。

## 版面

- 外框：頂端列固定在上方；側邊選單寬 208 px；主內容區左右留白 `clamp(16px, 3vw, 28px)`。
- 內容由卡片組成：白底、1 px 邊框、圓角 12 px、內距 14 × 16 px。卡片之間 16 px。工作台裡的幾個區塊（影片、字幕清單、時間軸）和提示訊息的圓角是 10 px。
- 按鈕和輸入框圓角 8 px；狀態標籤是膠囊形。
- 860 px 以下：側邊選單變成頂端列下方的一排按鈕（會換行），「管理」另起一行。
- 480 px 以下：電影卡片固定兩欄；動作按鈕靠左。
- 表格太寬時在自己的容器裡橫向捲動，頁面本身不捲。

## 元件

括號裡是原型 CSS 的類別名稱，方便對照。

| 元件 | 說明 |
| --- | --- |
| 按鈕 | 一般（白底、灰框）；主要（`.primary`，琥珀底，一頁通常只有一個）；強調（`.strong`，琥珀色的框和字，用在每一列的主要動作）；危險（`.danger`，紅底，只出現在確認框裡）；連結樣式（`.link`） |
| 切換鈕 | `aria-pressed="true"` 時反白（篩選、語言、同步/逐句編輯） |
| 欄位（`.field`） | 標籤在上、輸入框、下面一行說明；出錯時那一行換成紅色的錯誤訊息 |
| 開關（`.sw`） | 布林設定。一改就生效的用開關；要按儲存才生效的表單裡也可以用，但要有未儲存的提示 |
| 狀態標籤（`.st`） | 膠囊形，前面一個圓點。四種語意：完成/正常（綠）、注意（黃）、失敗（紅）、進行中（藍），加上中性的灰 |
| 說明框（`.banner`） | 整塊的訊息，有 `info`、`warn`、`bad` 三種。可以帶按鈕 |
| 確認框（`.confirm`） | 紅色淡底的小區塊，就地展開：一段說明、一個紅色按鈕、一個「先不要」 |
| 空狀態（`.empty`） | 虛線框。一句粗體說明發生了什麼，一句建議，需要時一個按鈕 |
| 進度條（`.prog`） | 8 px 高，琥珀色；失敗時紅色 |
| 用量色條（`.usage`） | 分段的橫條；大的版本 16 px 高，配圖例 |
| 分頁（`.tabs`） | 底線樣式；每個分頁標籤下面有一行小字說明現況 |
| 海報（`.poster`） | 2:3，圓角 8 px。有圖就放圖。沒有就畫佔位海報，樣子照原型：一塊純色的底，內側 5 px 處有一圈 1 px 的細白框（30% 透明）；上方是片名（Oswald、600、全大寫、可以斷行），下方是年份和片長（等寬字，「1963 · 113 分」）；字的顏色是 `--poster-ink`。三種大小：卡片（滿寬）、電影頁（最寬 190 px）、片庫清單（84 px）。下載頁的小縮圖（`.thumb`，44 × 62 px）只有色塊和年份 |
| 佔位海報的底色 | 原型裡每部示範電影有指定的顏色。正式版沒有這個資料：用片名算出一個固定的色相（同一部片永遠同一個顏色），飽和度和亮度固定在深色的範圍，例如 `hsl(<色相> 32% 26%)`，讓 `--poster-ink` 在上面有足夠的對比 |
| 流程標籤（`.flow`） | 片庫卡片上的三步驟，用箭頭連起來。完成的是綠色；做到一半的（有字幕但還沒確認）是黃色 |
| 彈出選單（`.pop`） | 通知和帳號選單。點外面或按 Esc 關閉 |
| 提示訊息（`.toast`） | 右下角，可以帶一個按鈕。顏色和頁面相反：底是 `--ink`、字是 `--panel`，所以淺色主題是深底淺字，深色主題是淺底深字 |
| 數字方塊（`.tile`） | 總覽頁：小標、一個大數字、一行說明，整塊可以點 |

不需要圖示庫。原型裡沒有任何圖示，全部用文字；品牌標記是一個用 CSS 畫的琥珀色小方塊（拍板的樣子）。

## 動態

幾乎沒有。進度條的寬度變化有 0.6 秒的線性過渡；開關有 0.15 秒。`prefers-reduced-motion` 時全部關掉。頁面切換、彈出選單、提示訊息都是直接出現。

## 數字怎麼寫

| 東西 | 規則 | 例子 |
| --- | --- | --- |
| 檔案大小 | 以 1024 為底。1 GB 以上寫 GB，一位小數，`.0` 省略；以下寫 MB，取到十位數；不到 10 MB 寫整數 MB | `1.6 GB`、`5 GB`、`880 MB`、`7 MB` |
| 用量指示 | 已用 / 上限 | `22.3 GB / 26 GB` |
| 速度 | MB/s，一位小數 | `11.8 MB/s` |
| 百分比 | 整數 | `43%` |
| 剩餘時間 | 分鐘；不到一分鐘寫「剩不到 1 分鐘」 | `剩約 12 分鐘` |
| 時間碼 | `時:分:秒,毫秒` | `00:01:23,456` |
| 清單裡的時間 | `分:秒.毫秒` | `01:23.456` |
| 位移 | 帶正負號，兩位小數，單位寫出來。負號用 `−`（U+2212）。兩個例外：可以編輯的輸入欄位裡是純數字（`-2.36`）；確認後的摘要用三位小數（`−2.360 秒`）。見 [09-sync-workbench.md](09-sync-workbench.md) | `−2.36 秒`、`+13.24 秒` |
| 速率 | `×` 加四位小數 | `×1.0427` |
| 相對時間 | 一天內寫「剛剛」「20 分鐘前」「2 小時前」；之後寫「昨天」「3 天前」「上週」「2 週前」；更久寫日期 | |
| 操作紀錄的時間 | 要看得出先後，所以帶時刻：「今天 09:14」「昨天 22:41」，更早寫日期加時刻 | `今天 09:14` |
| info hash | 頭 8 碼 + `…` + 尾 4 碼 | `2a457de5…7cd3` |

原型裡的大小是示範資料寫死的數字，而且它把 1 GB 當成 1000 MB 來顯示。正式版一律從位元組算、以 1024 為底，所以數字不會和截圖一模一樣。這不是錯誤。「不到 10 MB 寫整數」那一條是正式版加的（原型沒有這麼小的東西）。

## 文案

介面是繁體中文，用台灣的說法。原型裡的每一句話都可以直接用。寫新的句子時照下面的規則。

- **說人話，說完整。** 「空間不足。這個版本 5.9 GB，目前剩 5.6 GB，還差 300 MB。」而不是「儲存空間不足」。
- **錯誤訊息講發生了什麼，以及接下來可以怎麼做。** 「連不上 YTS。它的網域常常更換，可能又換了。到「來源設定」更新網址後再試。」
- **按鈕上寫的是它會做的事，而且前後一致。** 按鈕叫「匯出 MKV」，完成的提示就說「匯出完成」，不要一下「輸出」一下「產生」。
- **破壞性的動作講清楚後果，包含不會發生的事。** 「移除會刪除影片 1.9 GB，字幕也會一起刪掉。匯出的 MKV 不受影響。」
- **用這個產品自己的詞**（[01-product.md](01-product.md) 的名詞表）：版本、片庫、持有人、候選字幕、檢查點、對齊點、分段、預覽檔。成員看得到的頁面上不要出現 torrent、hash、proxy、cue、session 這類字（info hash 那一小段等寬字是唯一的例外）。管理頁不受這個限制：容器名稱、WebTorrent、ffmpeg、tracker、DHT、埠號這些技術名詞是管理員需要看到的，原型的管理頁也是這樣寫。
- **動作和狀態分開叫。** 使用者做的事叫「匯出」（「匯出 MKV」「開始匯出」「匯出完成」）；機器正在做的那個狀態叫「封裝中」；做好了叫「可以下載」。同樣的，「下載」是動作，「下載中」「排隊中」「分析中」是狀態。
- **不要客套。** 不寫「很抱歉」「請稍候片刻」「恭喜」。
- **標點**：用全形的逗號、句號、冒號、分號、問號、驚嘆號和全形括號（U+FF0C、U+3002、U+FF1A、U+FF1B、U+FF1F、U+FF01、U+FF08、U+FF09）；引號用「」；並列用頓號。原型的文案用的是半形的逗號、冒號、分號和括號，搬進文案檔時一律換成全形（機械式替換即可，數字裡的千分位逗號和時間碼的冒號不換）。
- **空格**：中文和英文、數字之間留一個半形空格（`這個版本 5.9 GB`、`連不上 YTS`），和原型一致；全形標點前後不加空格。
- **語言標籤**：繁體中文、簡體中文、English；還分不出繁簡的中文（`zh`）寫「中文（待判斷）」，判斷不出語言的（`und`）寫「語言待判斷」。來源的名稱：JustSubtitles、YIFY Subtitles、射手網（偽）、字幕庫；上傳的寫「手動上傳」。

所有文案集中在一個檔案（例如 `apps/web/src/copy/zh-TW.ts`），元件裡不直接寫中文字串。API 的錯誤代碼、通知的種類、操作紀錄的動作代碼，都在這個檔案裡對照成句子。

## 無障礙

- 焦點框：2 px 的 `--accent-fill`，往外 2 px。任何元件都不能把它拿掉。
- 每個輸入框都有關聯的 `<label>`。
- 狀態不能只靠顏色：標籤上有文字，色點有 `title`。
- 錯誤訊息用 `role="alert"`；會自己更新的區塊（工作台的訊息列、提示訊息）用 `aria-live="polite"`。
- 目前所在的選單項目用 `aria-current="page"`；分頁用 `role="tab"` 和 `aria-selected`；展開的選單按鈕有 `aria-expanded`。
- 表格用真的 `<table>`。
- 對比：主要文字和次要文字在兩種主題下都要達到 4.5:1。
