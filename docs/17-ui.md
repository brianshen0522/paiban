# 17 Visuals and copy

The way the prototype looks is the way it should be built. This document writes down its rules so the implementation doesn't have to guess from screenshots.

The full styles are in `prototype/platform/src/app.css` (platform) and `bench.css` (workbench). Together the two files are a little over four hundred lines and can serve directly as the starting point for the CSS: copy the tokens as they are, and turn the classes into components.

## Direction

Like a home video cabinet: a fixed top bar and a short side menu frame a working page. The page itself is quiet tables, cards and status tags; the only things with any color weight are the posters and one amber primary button.

Don't: gradient backgrounds, large hero banners, frosted glass, stacked shadows, icon libraries, animated transitions, cards with overly large rounded corners. (Exception: the confirmation dialog for destructive actions is a dialog with a shadow; see "Components".) This is a tool used every day, not a product landing page.

## Color

Everything is CSS custom properties. Users can pick one of three appearances (Brian, 2026-10-06): **Light, Dark, System** (the default). The choice is stored in this device's `localStorage` (`paiban.theme`) and written to `data-theme` on `<html>` (`light` or `dark`; not set for System). The CSS is `:root[data-theme="dark"]`, plus `:root:not([data-theme="light"])` with `prefers-color-scheme: dark`. To avoid a flash on load, the choice is applied by `public/theme-init.js` before the first paint (the CSP doesn't allow inline scripts, so it is a separate same-origin file). How to switch (changed by Brian, 2026-10-06): **one icon button**, on the right of the top bar (left of "Notifications"), and in the top-right corner of the sign-in, register and reset-password pages. Each press moves to the next one in the order "Light → Dark → System → Light", and the icon (sun, moon, screen) turns once and changes to the new one; it doesn't turn when the system setting "reduce motion" is on. The button's label text is "Appearance: 〈current〉. Click to switch to 〈next〉". At phone width, the storage meter's small bar and the limit are hidden and only the used amount stays (the limit is on the Storage page), so the brand and the buttons fit on the same row; the search box goes on a second row.

## Type

| Use | Font | `font-family` |
| --- | --- | --- |
| Interface | IBM Plex Sans; system fonts for Chinese | `"IBM Plex Sans", "PingFang TC", "Microsoft JhengHei", "Noto Sans TC", "Noto Sans CJK TC", system-ui, sans-serif` |
| Numbers, timecodes, file names, info hashes, offsets and rates | IBM Plex Mono, with `font-variant-numeric: tabular-nums` on | `"IBM Plex Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace` |
| Titles on placeholder posters | Oswald, all caps | `"Oswald", "PingFang TC", "Microsoft JhengHei", "Noto Sans TC", sans-serif` |

**Fonts are served by the site itself, not loaded from outside** (the prototype used Google Fonts for convenience; the real version must not). IBM Plex Sans, IBM Plex Mono and Oswald come from font packages on npm. For Chinese, the system's fonts come first (PingFang TC, Microsoft JhengHei); systems without them (Linux, Android) use Noto Sans TC served by the site itself (`@fontsource/noto-sans-tc`, 400, 500, 600). It is split by character range into about a hundred small files, and a page downloads only the slices it uses; Mac and Windows have their own fonts and don't download it (Brian, 2026-10-06: on Linux there used to be only one Chinese font with no bold, so headings and body text looked the same).

The font order differs from the prototype's CSS: the prototype put Noto Sans TC before the system fonts because it loaded that font from Google Fonts. The real version doesn't load it, so each platform's built-in Chinese font (PingFang TC on macOS and iOS, Microsoft JhengHei on Windows) comes first, and Noto is left for Linux and Android.

Weights: IBM Plex Sans uses 400, 500, 600; IBM Plex Mono uses 400, 500; Oswald uses 500, 600. Bundle only these.

Base size 14 px, line height 1.5. Page titles 21 px / 600; card titles 15 px / 600; help text 12.5 px; big numbers (usage) 28 px.

## Layout

- Shell: the top bar is fixed at the top; the side menu is 208 px wide; the main content area has side padding of `clamp(16px, 3vw, 28px)`.
- Content is made of cards: white background, 1 px border, a very faint shadow (`--shadow`, none in the dark theme), 12 px corner radius, 16 × 18 px padding. Table rows get a light gray background on hover. 16 px between cards. In the workbench, the few areas (video, subtitle lines, timeline) and toasts have a 10 px corner radius.
- Buttons and input boxes have an 8 px corner radius; status tags are pill-shaped.
- Below 860 px: the side menu becomes a row of buttons under the top bar (it wraps), with "Admin" on a line of its own.
- Below 480 px: film cards are fixed at two columns; action buttons align left.
- When a table is too wide it scrolls horizontally inside its own container; the page itself doesn't scroll.

## Components

The names in parentheses are the prototype's CSS classes, for easy comparison.

| Component | Description |
| --- | --- |
| Button | Minimum height 34 px, weight 500. Normal (white background, gray border); primary (`.primary`, amber background, usually only one per page); strong (`.strong`, light amber background `--accent-wash`, amber text and a semi-transparent border, used for the main action in each row); danger (`.danger`, red background, only appears in confirmation dialogs); link style (`.link`). Full-width buttons center their text |
| Toggle button | Inverted when `aria-pressed="true"` (filters, languages, Sync/Edit lines) |

| Status tag (`.st`) | Pill-shaped, with a dot in front, **light background, no border** (`--good-wash` with `--good` text, and so on). Four meanings: done/working (green), attention (yellow), failed (red), in progress (blue), plus a neutral gray (`--panel-2` background) |
| Banner (`.banner`) | A block message in three kinds, `info`, `warn` and `bad`: light background, very faint border, a 3 px strip of the meaning's color on the left. Can carry a button |

In the workbench, the "some checkpoints haven't been heard yet" question is not a destructive action and still appears in place below the confirm button |
| Empty state (`.empty`) | Dashed border. One bold sentence saying what happened, one suggestion, and a button when needed |
| Progress bar (`.prog`) | 8 px high, amber; red on failure |
| Usage bar (`.usage`) | A segmented horizontal bar; the large version is 16 px high, with a legend |
| Tabs (`.tabs`) | Underline style; under each tab label is a line of small text describing the current state |
| Poster (`.poster`) | 2:3, 8 px corner radius. If there is an image, show it. If not, draw a placeholder poster that looks like the prototype's: a solid-color background with a thin 1 px white frame (30% transparent) 5 px inside the edge; the title at the top (Oswald, 600, all caps, may wrap), the year and running time at the bottom (monospace, "1963 · 113 min"); text color `--poster-ink`. Three sizes: card (full width), film page (at most 190 px wide), Library list (84 px). The small thumbnail on the Downloads page (`.thumb`, 44 × 62 px) has only the color block and the year |
| Placeholder poster color | In the prototype each demo film has an assigned color. The real version has no such data: derive a fixed hue from the title (the same film always gets the same color), with saturation and lightness fixed in a dark range, e.g. `hsl(<hue> 32% 26%)`, so `--poster-ink` has enough contrast on top of it |

No icon library is needed. The prototype has no icons at all, only text; the brand mark is a small amber square drawn in CSS (the look of a clapperboard, as in the name Paiban (拍板)).

## Motion

Almost none. Progress bar width changes have a 0.6-second linear transition; switches have 0.15 seconds. All of it is off under `prefers-reduced-motion`. Page changes, pop-up menus and toasts all appear instantly.

## How to write numbers

| Thing | Rule | Example |
| --- | --- | --- |
| File size | Base 1024. 1 GB and above in GB with one decimal, dropping `.0`; below that in MB, rounded to tens; under 10 MB as whole MB | `1.6 GB`, `5 GB`, `880 MB`, `7 MB` |
| Usage indicator | Used / limit | `22.3 GB / 26 GB` |
| Speed | MB/s, one decimal | `11.8 MB/s` |
| Percentage | Whole number | `43%` |
| Time left | Minutes; under a minute write 「剩不到 1 分鐘」 ("less than a minute left") | `剩約 12 分鐘` ("about 12 minutes left") |
| Timecode | `hours:minutes:seconds,milliseconds` | `00:01:23,456` |
| Times in lists | `minutes:seconds.milliseconds` | `01:23.456` |
| Offset | Signed, two decimals, unit written out. The minus sign is `−` (U+2212). Two exceptions: editable input fields hold a plain number (`-2.36`); the summary after confirming uses three decimals (`−2.360 秒`, seconds). See [09-sync-workbench.md](09-sync-workbench.md) | `−2.36 秒`, `+13.24 秒` |
| Rate | `×` plus four decimals | `×1.0427` |
| Relative time | Within a day: 「剛剛」 ("just now"), 「20 分鐘前」 ("20 minutes ago"), 「2 小時前」 ("2 hours ago"); after that 「昨天」 ("yesterday"), 「3 天前」 ("3 days ago"), 「上週」 ("last week"), 「2 週前」 ("2 weeks ago"); older than that, a date | |
| Times in the activity log | The order has to be visible, so include the time of day: 「今天 09:14」 ("today 09:14"), 「昨天 22:41」 ("yesterday 22:41"); earlier ones as a date plus time | `今天 09:14` |
| info hash | First 8 characters + `…` + last 4 | `2a457de5…7cd3` |

The sizes in the prototype are numbers hard-coded in the demo data, and it displays 1 GB as 1000 MB. The real version always computes from bytes in base 1024, so the numbers won't match the screenshots exactly. That is not a bug. The "under 10 MB as whole MB" rule was added for the real version (the prototype has nothing that small).

## Copy

The interface comes in Traditional Chinese and English (Brian, 2026-10-08). Each person picks one, stored in their account; without a choice it follows the browser (Chinese browser languages get Traditional Chinese, English ones get English, anything else gets Traditional Chinese). The Traditional Chinese uses Taiwan usage, and every sentence in the prototype can be used as is. When writing new sentences, follow the rules below; the English version follows the same spirit (speak plainly, state consequences, no pleasantries), uses ordinary English punctuation, and its vocabulary mapping is in the comment at the top of `apps/web/src/copy/en.ts`.

The rules below are written for the Chinese copy; the Chinese examples are kept as they appear in the copy file.

- **Speak plainly, and say it all.** 「空間不足。這個版本 5.9 GB，目前剩 5.6 GB，還差 300 MB。」 ("Not enough space. This version is 5.9 GB, 5.6 GB is left, 300 MB short.") rather than 「儲存空間不足」 ("Insufficient storage").
- **Error messages say what happened and what you can do next.** 「連不上 YTS。它的網域常常更換，可能又換了。到「來源設定」更新網址後再試。」 ("Can't reach YTS. Its domain changes often and may have changed again. Update the address in Sources, then try again.")
- **A button says what it will do, and consistently.** If the button is called 「匯出 MKV」 ("Export MKV"), the completion notice says 「匯出完成」 ("Export finished"); don't switch between 「輸出」 ("output") and 「產生」 ("generate").
- **Destructive actions spell out the consequences, including what won't happen.** 「從你的片庫移除？美玲 還持有這部片，檔案不會刪除，也不會釋放空間。」 ("Remove from your library? 美玲 [a person's name] still holds this film, so the files won't be deleted and no space will be freed.")
- **Use the product's own words** (the glossary in [01-product.md](01-product.md)): 版本 (version), 片庫 (Library), 持有人 (holder), 候選字幕 (candidate subtitles), 檢查點 (checkpoint), 對齊點 (anchor), 分段 (segment), 預覽檔 (preview file). Words like torrent, hash, proxy, cue and session must not appear on pages members can see (the short monospace info hash is the only exception). Admin pages are not bound by this: technical terms like container names, WebTorrent, ffmpeg, tracker, DHT and port numbers are things administrators need to see, and the prototype's admin pages are written that way too.
- **Name actions and states differently.** What the user does is 「匯出」 ("export": 「匯出 MKV」, 「開始匯出」, 「匯出完成」); the state while the machine is doing it is 「封裝中」 ("packing"); when it's done it is 「可以下載」 ("Ready to download"). Likewise, 「下載」 ("download") is the action, and 「下載中」 ("Downloading"), 「排隊中」 ("Queued"), 「分析中」 ("Analyzing") are states.
- **No pleasantries.** Don't write 「很抱歉」 ("we're sorry"), 「請稍候片刻」 ("please wait a moment"), 「恭喜」 ("congratulations").
- **Punctuation**: use full-width commas, periods, colons, semicolons, question marks, exclamation marks and full-width parentheses (U+FF0C, U+3002, U+FF1A, U+FF1B, U+FF1F, U+FF01, U+FF08, U+FF09); quotation marks are 「」; list items are separated by the enumeration comma 、. The prototype's copy uses half-width commas, colons, semicolons and parentheses; when moving it into the copy file, change them all to full-width (a mechanical replacement is fine; thousands separators in numbers and colons in timecodes stay as they are).
- **Spacing**: put one half-width space between Chinese and English or numbers (`這個版本 5.9 GB`, `連不上 YTS`), as in the prototype; no spaces around full-width punctuation.
- **Language labels**: 繁體中文 (Traditional Chinese), 簡體中文 (Simplified Chinese), English; Chinese whose script isn't determined yet (`zh`) is 「中文（待判斷）」 ("Chinese (unconfirmed script)"), and an undetermined language (`und`) is 「語言待判斷」 ("Unknown language"). Source names: JustSubtitles, YIFY Subtitles, 射手網（偽） (Assrt (Shooter)), 字幕庫 (Zimuku); uploads are 「手動上傳」 ("Uploaded").

All copy lives in the copy files: `apps/web/src/copy/zh-TW.ts` is the baseline, `en.ts` must have exactly the same keys (the type check enforces it), and components always get `t` from `apps/web/src/copy` (`index.ts`) and never contain strings in any language directly. API error codes, notification kinds and activity log action codes are all mapped to sentences in the copy files, so notifications and the activity log also follow the viewer's language. Dates, numbers and language names are formatted with `Intl` according to the current language (`intlLocale()`). Film titles: the Chinese interface shows TMDB's Chinese title first with the original title below; the English interface does the opposite, original title first and Chinese title below (`filmTitle()`). The film page's summary: the Chinese interface uses TMDB's Chinese summary, the English interface uses YTS's English summary (`MovieDetail.summaryEn`), falling back to the other when one is missing. Changing language redraws the whole page without a reload.

Names the server writes into data for others to see later use the language of **the person who did it**: the version name of AI-translated subtitles ([18-llm.md](18-llm.md)) and the subtitle track titles in an exported MKV ([08-media-pipeline.md](08-media-pipeline.md)).

## Accessibility

- Focus ring: 2 px of `--accent-fill`, offset 2 px outward. No component may remove it. Text input boxes and menus are the exception: the border becomes `--accent-fill`, with an extra 3 px semi-transparent amber ring (`--ring`) outside, which is just as visible.
- Every input box has an associated `<label>`.
- State must not rely on color alone: tags have text, and colored dots have a `title`.
- Error messages use `role="alert"`; areas that update by themselves (the workbench message bar, toasts) use `aria-live="polite"`.
- The current menu item uses `aria-current="page"`; tabs use `role="tab"` and `aria-selected`; menu buttons that expand have `aria-expanded`.
- Tables use real `<table>`.
- Contrast: main and secondary text must reach 4.5:1 in both themes.

## Layout: the window doesn't scroll (Brian, 2026-10-06)

- The whole window never scrolls: the top bar and menu are fixed, and the content area sits beneath them.
- **Pages built around one list** (Search, Downloads, Library, Activity log) exactly fill the content area: the title and filters stay put, and only the list scrolls inside its own frame (`FillPage` and `ScrollList`; the frame can be scrolled with the keyboard).
- **Pages with several lists**: each table gets its own frame, at most 60% of the screen height (at most 560 px), with the header staying at the top while scrolling; the Overview's activity and issue lists work the same way. When the page as a whole still exceeds one screen (forms, the workbench), it is the content area that scrolls; the top bar and menu don't move.
- At phone width, the menu becomes one row that can be swiped sideways, leaving the height for the list.
- The sign-in, register and reset-password pages scroll themselves (so the form still fits on short phones).
